# Skylanders Archive: Lightweight Default View + URL Routing

**Date:** 2026-06-23
**Status:** Approved

## Summary

Loading the Skylanders archive (curation and published builds alike, both
generated by `scripts/reclassify-tumblr.mjs`) is slow because the initial,
nothing-selected state renders a DOM card for every image across every
game and category at once (~1,700+ `<img>` elements built synchronously in
one loop). This redesign makes the bare initial state a lightweight message
instead, while leaving the existing "All Images" full-dump view completely
intact and reachable — and adds URL hash routing across all archive views
so browser back/forward works and views are deep-linkable, addressing both
parts of the original ask in one pass since they touch the same render
pipeline.

## Context

- **Root cause** (`scripts/reclassify-tumblr.mjs:2841-2854`, inside
  `renderGrid()`): when `sel = {game: null, cat: null, char: null}` and no
  `annFilter`/`query` is active, the final `else` branch sets
  `games = sel.game ? [sel.game] : GO` — since `sel.game` is `null` on
  first load, this iterates **every** game and category, calling
  `addSection()` → `makeCard()` for every image in the archive.
- **`render()`** (`reclassify-tumblr.mjs:3136`) is the single function
  called after every state mutation: `renderSidebar(); renderGrid();
  renderCharPanel(); ...`. This is the one integration point for hash
  syncing — no need to touch the ~10 individual `sel = {...}; render();`
  call sites scattered through the file.
- **The sidebar already provides full navigation** (`renderSidebar()`,
  `reclassify-tumblr.mjs:2025-2207`): an "All Images" entry (sets `sel =
  {game:null, cat:null, char:null}` — today's slow default, unchanged
  behavior), Backgrounds/Details annotation filters, a collapsible
  per-game list with category counts, and a cross-cutting by-character
  index. Nothing here needs to change — the fix is entirely about what
  renders in `#main` *before* anything is clicked, not about navigation
  itself.
- **Existing hash usage that must not be disturbed:** `model-viewer.js`
  reads `#model=<id>` / `#texture=<id>` on load (`model-viewer.js:44-50`)
  and writes them via `history.replaceState` (`model-viewer.js:459,540`).
  `reclassify-tumblr.mjs:3245` reads `#pose=<name>` once at bootstrap for
  the pose-editor deep link. Both are narrow, `key=value`-shaped hashes
  with no path segments — the new routing scheme (below) never collides
  with them, and must explicitly skip syncing whenever either feature is
  active (`mvActive` or `poseDetailChar` truthy) so it doesn't fight their
  own `replaceState` calls.
- **`renderDashboard(g)`** (`reclassify-tumblr.mjs:2625-2625+`) is the
  existing lightweight per-game view: category cards with only their
  first 6 images previewed. This already exists and is already fast —
  the new landing state is *not* a reimplementation of this, it's what
  shows before any game is picked.

## Decisions Made

| Question | Decision |
|---|---|
| Should "browse everything" be removed? | No — kept exactly as-is, just no longer automatic on load |
| New landing UI | A short message + a "Browse everything" link in `#main`, not a duplicate tile grid (the sidebar already lists every game with counts) |
| Should search text (`query`) be part of the URL? | No — excluded from the hash scheme; preserving it across back/forward isn't worth hash-writing on every keystroke |
| Routing mechanism | Hash-based (`#...`), not path-based — Neocities is a static host with no server-side rewrites, so a direct link/refresh to a `pushState`-only path would 404. The hash is never sent to the server, so it always works. |
| History granularity | Coarse navigation (game/category/char/all/landing) gets real `pushState` entries (back-button-able, per the original request). Fine-grained sub-state already managed elsewhere (model-viewer texture switching, pose editor) keeps using its own existing `replaceState`-only handling, untouched. |

## Design

### 1. State → slug mapping

| Hash | State |
|---|---|
| `#` (empty) | Landing: nothing selected (**new** — replaces today's implicit full dump) |
| `#all` | Full dump, all games (today's "All Images" — unchanged) |
| `#ann/background`, `#ann/detail` | The existing Backgrounds/Details filters |
| `#<game>` | Per-game dashboard (existing `renderDashboard`) |
| `#<game>/<category>` | Category grid |
| `#char/<name>` | Character profile (`name` is `encodeURIComponent`'d, matching the existing `#pose=` pattern's `decodeURIComponent` use) |

`<game>` and `<category>` are the existing slug IDs already used as `TREE`
object keys (e.g. `lost-islands`, `character-art`) — no new encoding
needed there.

### 2. The `viewAll` flag

Today, clicking "All Images" and the true initial page load produce the
*identical* `sel = {game:null, cat:null, char:null}` state — `renderGrid()`
can't currently tell them apapart. A new module-level `let viewAll =
false;` resolves this:

- Set to `true` only by the "All Images" sidebar click handler
  (`reclassify-tumblr.mjs:2032`) and when parsing `#all` from the hash.
- Starts `false` at bootstrap, and every other navigation action
  (selecting a game/category/char) makes it irrelevant anyway, since
  `renderGrid()`'s dispatch checks `sel.game`/`sel.cat`/`sel.char` first —
  `viewAll` only matters when all three are falsy.
- `renderGrid()`'s existing final `else` branch (the one that currently
  always dumps everything) gets one new guard at its top: if `!viewAll`,
  render the new landing content instead of looping `GO`. If `viewAll` is
  true, fall through to the exact existing loop, unchanged.

### 3. Landing content

When `!viewAll` and nothing else is selected, `#main` shows a short
message ("Pick a game from the sidebar to start browsing.") and a single
"Browse everything (`<total>` images)" link that sets `viewAll = true` and
calls `render()` — equivalent to clicking "All Images" today. No new tile
grid; the sidebar already lists every game with its image count.

### 4. Hash sync (`syncHash()`, called at the end of `render()`)

```
function hashFromState() {
  if (mvActive || poseDetailChar) return null; // those features own the hash themselves
  if (annFilter) return '#ann/' + annFilter;
  if (sel.char) return '#char/' + encodeURIComponent(sel.char);
  if (viewAll) return '#all';
  if (sel.game && sel.cat) return '#' + sel.game + '/' + sel.cat;
  if (sel.game) return '#' + sel.game;
  return '#';
}
```

`syncHash()` calls `hashFromState()`; if it returns `null` (model viewer or
pose editor active), do nothing — leave the hash exactly as those features
left it. Otherwise, if the computed hash differs from `location.hash`,
`history.pushState(null, '', hash)`. A guard flag (`_navigatingFromHistory`,
set just before re-rendering from a `popstate` event and cleared right
after) prevents that re-render's own `syncHash()` call from pushing a
*new* entry on top of the one the user just navigated back to.

### 5. Parsing (`parseHash()`, called once at bootstrap before the first
`render()`, and from a new `popstate` listener)

Skip entirely (return without touching any state) if the hash matches
`/^#(model|texture|pose)=/` — those are parsed by their own existing code
already. Otherwise:

- `#all` → `viewAll = true`, clear `sel`/`annFilter`.
- `#ann/<x>` → `annFilter = x` (only if `x` is `'background'` or
  `'detail'`; otherwise fall through to landing).
- `#char/<name>` → `sel.char = decodeURIComponent(name)`, but only if a
  case-insensitive match exists in `SKYLANDERS` — otherwise fall through
  to landing.
- `#<game>` or `#<game>/<category>` → only if `game` is a real `GAMES`
  entry or `'misc'`; `category`, if present, only if it's a real key of
  `TREE[game]`. `expanded.add(game)` so the sidebar shows the matching
  section open. Invalid game/category → fall through to landing.
- Anything else (including a literally empty hash) → landing: `sel =
  {game:null, cat:null, char:null}`, `annFilter = null`, `viewAll = false`.

### 6. `popstate` listener

```
window.addEventListener('popstate', () => {
  _navigatingFromHistory = true;
  parseHash();
  render();
  _navigatingFromHistory = false;
});
```

## Error Handling / Edge Cases

- **Invalid/stale hash** (typo'd game, deleted category, unknown
  character name): `parseHash()`'s validation (above) falls back to the
  landing state rather than rendering a broken or empty grid.
- **Collision with `#model=`/`#texture=`/`#pose=`:** explicitly excluded
  by the leading regex check in `parseHash()`, and `hashFromState()`
  returns `null` (no-op) whenever those features are active, so neither
  side ever overwrites the other's hash.
- **Rapid back/forward clicking:** `pushState` only fires when the
  computed hash actually differs from the current one, so no duplicate
  history entries pile up from re-renders that don't change state.
- **Direct link to a deep state** (e.g. a bookmark to
  `.../archive/#imaginators/character-art`): handled by the same
  `parseHash()` path as `popstate` — called once at bootstrap, before the
  first `render()`.

## Testing

No test framework in this project (consistent with prior work). Manual
verification via the dev server, in both curation and published builds:

1. Load the archive page fresh (no hash) — confirm `#main` shows the
   landing message immediately, not a multi-second full-archive render.
2. Click "Browse everything" — confirm it shows the exact same full dump
   as today's "All Images" sidebar entry, and the hash becomes `#all`.
3. Click through sidebar: a game, then a category, then a character —
   confirm the hash updates to `#<game>`, then `#<game>/<category>`, then
   `#char/<name>` at each step.
4. Use the browser back button repeatedly from step 3 — confirm each step
   reverses correctly (back to category view, back to game view, back to
   landing) and the sidebar's highlighted/expanded state matches the
   restored view.
5. Load the page directly at a deep-link hash (e.g.
   `#trap-team/character-art`) — confirm it renders that category
   directly with the correct sidebar section expanded, instead of landing.
6. Load directly at an invalid hash (e.g. `#not-a-real-game`) — confirm it
   falls back to the landing state without errors.
7. Open the embedded 3D model viewer (sets `#model=...`) and the pose
   editor (sets `#pose=...`) — confirm neither gets its hash clobbered by
   this feature's `syncHash()`, and confirm both still work exactly as
   before.
